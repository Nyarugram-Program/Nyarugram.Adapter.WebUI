# 独立复核 Prompt

请复核 Nyarugram.Adapter.WebUI 的 Milky 与多协议改造交付。先读 AGENTS.md、Docs/MILKY-INTEGRATION.md、Docs/MANAGEMENT-API.md，以及实施 agent 的交付记录，再检查实际源码和运行结果。

目标是确认浏览器能真实接入 Milky，同时保留 OneBot V11 与多实例能力。不要仅凭页面名称变化、构建成功或替身响应判断完成。

## 复核重点

- 业务协议和管理模式是否分离，是否仍将 Milky 强行套入 OneBot 的配置、消息段、事件或错误外壳。
- Milky 是否正确调用 /api/{action}、/event 及能力扩展，入口是否显式配置。
- OneBot 标准 HTTP/WebSocket 路径是否通过回归，尚为空仓库的 Nyarugram.OnebotV11 是否被如实标记。
- NapCat 专属管理兼容是否彻底移除：管理模式、令牌、QQ 登录、OB11Config、网络/日志/系统状态、端口推断和专属响应模型均不应残留。
- 旧 `managementKind=napcat` 实例是否按策略迁移为 `onebot11 + none`，是否保留稳定 ID/名称/显式业务入口，是否清除旧管理凭据且不转为业务凭据；迁移是否可重复执行。
- 新实例是否只有两种管理模式，已移除路由/深链接是否有明确处理。
- 没有管理 API 时是否提供明确可用的纯协议模式。/admin/v1 是否真正由适配器实现，并复用实际账号服务。
- 切换实例、退出或重新认证时，缓存、凭据、请求、SSE、WebSocket、重连和媒体是否完整隔离。
- 管理会话、业务凭据和后端 Bearer 是否分别管理，秘密是否进入 URL、localStorage、日志、截图或导出数据。
- 配置读取是否脱敏，秘密更新是否区分保持、替换和清除，版本冲突与实际生效状态是否正确。
- epoch 是否在事件、恢复响应、ACK/resume 中贯穿，旧任务是否可能确认新连接事件，断线、重复、缺口和缓冲上限是否可恢复。
- JSON 整数是否损失精度，标准协议字段、管理 DTO 和原始编辑器是否各自遵守契约。
- 默认页面是否仍访问公网音乐、一言、QQ 头像或其他预置服务。
- 静态资源、SPA 路由、子路径、业务 API 和管理 API 是否能同时部署。
- 真实媒体不可用时界面是否准确，呼叫控制测试是否被写成真实双向语音成功。
- 锁文件、依赖版本、许可证、产物哈希和干净环境构建是否可复现。

## 执行验证

按仓库既有命令执行类型检查、构建及相关回归。依赖与缓存新增内容放 D 盘。浏览器验证至少包括 Milky 查询与消息收发、事件重连、OneBot HTTP/WebSocket 回归、账号登录和配置生效，并检查网络请求不含 NapCat 专属管理端点。

使用隔离账号和数据库，禁止向正式用户数据写入测试样本。访问条件不足时明确哪些部分仅进行了静态检查、替身测试或构建。

## 输出要求

优先列出会影响数据、凭据、协议兼容及实际可用性的具体问题，附文件和准确位置、触发条件、影响及修复方向。区分已复现与静态推断，说明实际执行的测试数量、失败及跳过。

随后给出按原始目标逐项的完成情况，分别列出前端、适配器管理接口、真实服务互操作、迁移和真实媒体验证状态。未发现问题时直接说明已检查范围和未覆盖条件。

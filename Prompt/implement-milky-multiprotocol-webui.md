# 实施 Prompt

请直接开发 Nyarugram.Adapter.WebUI，使其适配现有 Nyarugram.Milky，同时保留 OneBot V11 及多实例能力。完成前端、必要的管理面协同实现、回归和可独立部署的交付物。

先阅读根目录 AGENTS.md、Docs/MILKY-INTEGRATION.md、Docs/MANAGEMENT-API.md，再核对实际源码和同级适配器。遵循各仓库 AGENTS.md，保留全部已有修改。遇到真正需要外部输入的部分，先推进不依赖它的工作。

## 已知基线

当前前端来自 NapCat WebUI，采用 React、TypeScript、Vite、NextUI、Redux Toolkit、Monaco 和 xterm。现有 QQLogin、OB11Config、日志和认证接口依赖 NapCat。

Nyarugram.Milky 已有业务 API、/event、/health 和 CLI 账号操作，统一 /admin/v1 管理接口尚未实现。Nyarugram.OnebotV11 当前为空仓库，不能宣称已经和它完成联调。

Nyarugram.Milky 真实媒体仍未完成。呼叫控制、Loopback 及自动化测试结果与真实双向语音分别记录。

## 实施要求

### 1. 固定构建基线

- 检查已有环境，新下载依赖和缓存放 D 盘，默认 D:\BotgramBuild。
- 选择包管理器、固定工具版本、修正锁文件忽略规则，执行冻结安装和独立构建。
- 保留 MIT 许可证及版权，更新产品名称和实际项目说明，记录上游来源。
- 复用原组件体系，避免无关依赖升级和格式化。

### 2. 拆分业务协议与管理模式

- 支持 onebot11 和 milky 的业务协议选择，以及 napcat、nyarugram-admin-v1、none 三种管理模式。
- 新建实例模型及实例选择，显式配置管理、业务 HTTP、事件入口。移除通过端口替换推断入口的逻辑。
- 将全局 storeURL、token 和 OneBotConfig 的使用限制到对应实例与模式。
- 公共 UI 复用布局和表单，协议专属配置、API 目录、消息段与事件模型保持独立。
- 切换实例、账号或页面时取消旧请求、连接及重连任务，验证迟到结果隔离。

### 3. 先交付可真实使用的 Milky 数据模式

- 在 managementKind=none 下接入当前 Milky 实例，账号可由 CLI 预先登录。
- 支持基础系统、用户、联系人、群、成员、发送、消息查询、历史及已读动作。
- 使用固定 Milky schema，参数、响应和支持集合可校验。发送支持真实 text、可表达的 mention 和 reply。
- 支持标准 SSE/WebSocket 事件及 Nyarugram epoch 确认扩展，正确 ACK、resume、去重、缺口显示和重连。
- 保留 OneBot V11 HTTP/WS 调试、事件分类及原 NapCat 管理模式，执行回归。
- 没有实现的管理或业务功能明确展示状态，禁止伪造成功响应。

### 4. 实现统一管理面并联调

- 根据 Docs/MANAGEMENT-API.md 固定精确契约，至少完成实例信息、管理会话、Nyarugram 账号登录/退出、脱敏配置及版本校验、保存/生效状态、日志与运行指标。
- 优先在同级 Nyarugram.Milky 中实现相应 /admin/v1 接口，并遵循其开发要求。普通源码协同修改按任务范围执行。
- 适配器业务持久化保持 PostgreSQL-only，访问 Nyarugram 后端保持 Protobuf-only。
- 管理登录、业务访问凭据与账号会话分离，后端 Bearer 留在适配器。
- 当前 OnebotV11 尚未实现时，交付可复用管理契约和契约测试。避免扩大为完整实现整个 OneBot 后端。
- 前端管理 API 替身仅用于开发和测试，真实管理联调单独验收。

### 5. 处理自部署及通话页面

- 移除或默认关闭自动公网音乐、一言、QQ 头像和其他非必要网络服务请求，改成本地资源或显式配置。
- 所有真实服务入口由部署者配置，文档示例采用私网地址，不提供默认公共服务。
- 按真实 capability 展示发起、接听、拒接、挂断、状态和诊断。
- calls.voice=false 时准确展示媒体不可用。当前任务不以修改能力开关冒充真实引擎实现。
- 有真实媒体能力时按已实现契约接入浏览器音频，并执行真实双向声音测试；没有条件时交付控制面与明确限制。

### 6. 验证和交付

- 完成类型检查、构建及针对协议、实例隔离、能力、认证、配置冲突、事件恢复和整数精度的自动化测试。
- 在浏览器检查桌面和窄屏布局，执行真实 Milky 基础查询、私聊/群聊发送、事件接收和重连。
- 验证原 OneBot/NapCat 路径，记录所用服务或替身版本。
- 完成管理登录、真实账号登录、配置保存与生效、脱敏日志的真实服务联调。
- 构建可独立部署静态产物，验证同源托管、SPA 路由和子路径。
- 更新 README、支持矩阵、运行说明和交付报告，保留历史记录。输出产物路径、版本及 SHA-256。
- 明确源码实现、自动化测试、浏览器测试、真实服务和媒体设备验证各自状态。

## 必测场景

1. OneBot 与 Milky 来回切换，请求、缓存、凭据、事件和日志不串实例。
2. 请求途中退出、账号变化或切换实例，迟到结果不会恢复旧状态。
3. Milky 普通消息事件与确认扩展分别工作，旧 epoch ACK 被拒绝，显式恢复采用新 epoch。
4. 不支持、未配置、401、403、404、409/412、429 和服务不可达有明确呈现。
5. 配置秘密保持、替换、清除及并发管理员修改正确处理。
6. 没有管理 API 时仍可使用现有 Milky 业务调试，管理功能有明确不可用原因。
7. 标准协议 ID 保持精度，未知事件和错误响应仍可查看原始内容。
8. 默认加载页面不访问预置公网功能服务，不携带真实凭据到第三方目标。

最终回复逐项说明完成内容、代码位置、测试证据和剩余条件。正式部署、发布和数据迁移遵循已有明确授权。
